### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

1) Можно подавать заявку на кредит путем отправки письма с сайта\Интернет-банка. Менеджер вручную подтвердит лид и заведет заявку в АБС.
Плюс: своеобразная защита от автоматического спама в БД АБС. 
Минус: не уходим от ручной обработки.

2) В MVP сделать полноценный микросервис Заявок и request flow.
Плюс: не будет доп нагрузки на АБС.
Минус: большая миграция данных; можем не успеть, есть более приоритетные задачи.

**Недостатки, ограничения, риски**

| **№** | **Недостатки**                                                                                  | **Комментарий**                                                                                                                                                                                                 |
|:-----:|:------------------------------------------------------------------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|  1.   | Прямая работа с API АБС.                                                                        | На данном этапе дополнительная работа с API АБС предполагается только в части размещения заявок из Интернет-банка.                                                                                              |
|  2.   | Дополнительная нагрузка на БД АБС.                                                              | Поток заявок из Интернет-банка пойдет в БД АБС. Вариант минимизации риска:<br/>1) Запуск MVP в "пилотных" регионах, что ограничит кол-во заявок<br/>2) параллельно пишем новую платформу сопровождения клиента. |
|  3.   | К потоку заявок из нового источника может быть не готова не только БД АБС, но и штат бэк-офиса. | Вероятно, бизнес учитывает данный факт; возможно изначальный поток заявок не будет слишком большим (например, на стадии "MVP в проде" можно не давать рекламу новой функциональности).                          |
|  4.   | Необходимо обращаться к подрядчику системы Колл-центра для доработки | |                                                                                                                                                                                                                |
|  5.   | Предрасчет персональных ставок, что создаст доп. нагрузку на систему Скоринга | Путь минимизации риска: на текущем этапе работаем над масштабированием Скоринга |
